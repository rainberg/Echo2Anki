## 1. 项目概述

Anki 德语听力平台是一个面向德语学习者的多用户 SaaS 平台，核心功能是将德语音频自动转录为带时间戳的句子，生成逐句音频片段，并提供中文翻译、收藏集管理、Anki 推送等功能。

### 1.1 核心业务流程

```
用户上传音频 → 预扣费用 → 音频标准化 → Whisper 转录 → 生成逐句片段 → 结算费用
                                                              ↓
                                              字幕播放器（播放+高亮+选择收藏）
                                                              ↓
                                              收藏集管理 → Anki 推送（自建服务器 / AnkiWeb）
```

### 1.2 计费模型

- 预扣 → 结算 → 退还（reserve / settle / refund）
- 按音频时长计费（分钟为单位），不同引擎差异化定价
- 预扣金额 = 音频时长 × 引擎单价，结算后退还多余部分
- **计费由独立认证服务管理**，本地 anki DB 的 credits 会在用户登录时被 `_sync_local_user` 同步覆盖

### 2.3 认证服务架构

认证服务是**独立部署**的微服务，由其他部门维护，是用户认证和 credits 管理的**权威来源**。本仓库不包含认证服务源码。

```
认证服务 (auth-service, :9000)
  ├── /api/auth/*      → 认证路由 (注册/登录/刷新/验证)
  ├── /api/credits/*   → Credits 路由 (余额/预扣/结算/退还/充值/日志)
  └── /api/admin/*     → 管理员路由 (用户管理/充值/角色/日志)
```

**关键设计**：
- 后端通过 `auth_client.py` 调用认证服务 API
- Token 由认证服务签发，后端通过 `/api/auth/verify` 验证
- Credits 操作（reserve/settle/refund）全部通过认证服务完成
- 本地 anki DB 的 `users.credits` 仅是缓存，登录时从认证服务同步
- 后端 `.env` 中 `ANKI_AUTH_SERVICE_URL=http://127.0.0.1:9000`（本地调用，不走公网）

## 4. 数据库

### 4.1 连接信息

| 参数 | anki 数据库 | auth 数据库 |
|------|-------------|-------------|
| Host | localhost:5432 | localhost:5432 |
| 数据库名 | anki | auth_db |
| 用户 | anki | auth_user |
| 密码 | 服务器 .env 中配置 | 服务器 .env 中配置 |

> **重要**：通过 `sudo -u postgres psql -d anki` 连接后，需先执行 `SET search_path TO public;`

### 4.2 anki 数据库表结构 (15 张表)

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `users` | 用户 | id(UUID), email, role, credits, credits_reserved, allowed_engines, is_active |
| `engine_pricing` | 引擎定价 | engine_key + model_size (复合主键), credits_per_minute |
| `tasks` | 音频处理任务 | user_id, upload_name, file_hash, stage, progress, engine, segment_count, credits_charged, credits_reserved, is_public |
| `segments` | 句子片段 | task_id, seq_index, start_time, end_time, german_text, chinese_text, clip_path |
| `collections` | 收藏集 | user_id, name, description |
| `collection_items` | 收藏集条目 | collection_id, segment_id, push_enabled |
| `tags` | 标签 | user_id, name, color |
| `task_tags` | 任务-标签关联 | task_id, tag_id (复合主键) |
| `billing_records` | 计费记录 | user_id, task_id, action(reserve/settle/refund), amount, balance_after |
| `anki_push_configs` | Anki 推送配置 | user_id, push_mode(sync_client/ankiweb), sync_password_enc, ankiweb_password_enc |
| `push_records` | 推送记录 | user_id, task_id, collection_id, push_mode, card_count, status |
| `push_record_items` | 推送记录明细 | push_record_id, segment_id, status |
| `public_shares` | 公共分享 | task_id, user_id, title, difficulty, category, play_count, like_count, collect_count |
| `public_likes` | 公共点赞 | user_id + share_id (复合主键) |
| `public_collects` | 公共收藏 | user_id, share_id, collection_id |

### 4.3 索引

- `users.email` — 唯一索引
- `tasks.user_id + file_hash` — 唯一约束 (防重复上传)
- `tasks.stage` — 索引
- `tasks.is_public` — 索引
- `tasks.created_at` — 索引
- `segments.task_id + seq_index` — 唯一约束
- `segments.german_text` — GIN 索引 (pg_trgm, 模糊搜索)
- `segments.chinese_text` — GIN 索引 (pg_trgm, 模糊搜索)

### 7.4 充值操作

充值必须通过认证服务管理员 API，不能直接改本地数据库（本地 credits 会在登录时被覆盖）。

```bash
# 1. 获取管理员 token
curl -s http://127.0.0.1:9000/api/auth/login/password \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@3mudi.com","password":"Admin2026!"}'

# 2. 充值 (替换 ADMIN_TOKEN 和 USER_ID)
curl -s -X POST http://127.0.0.1:9000/api/admin/users/{USER_ID}/add-credits \
  -H 'Authorization: Bearer ADMIN_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"amount":"5000","remark":"管理员充值"}'

# 3. 同步本地 anki DB (用户下次登录时也会自动同步)
sudo -u postgres psql -d anki -c "SET search_path TO public; UPDATE users SET credits = (SELECT credits FROM users WHERE id = 'USER_ID') WHERE id = 'USER_ID';"
```

## 11. 已知问题与待办

### 11.1 已知问题

1. **前端主包过大**：index.js 约 1.5MB (gzip 419KB)，建议后续做代码分割 (dynamic import / manualChunks)
2. **充值功能**：当前为手动模式（提示联系管理员），未接入在线支付
3. **Anki 推送**：AnkiWeb 模式尚未完全验证，sync_client 模式依赖自建 Anki 同步服务器

5. **数据库 search_path**：通过 `sudo -u postgres psql -d anki` 连接后，需要先执行 `SET search_path TO public;` 才能查询表
6. **死代码 auth.py**：~~`backend/app/auth.py`~~ 已删除（无任何导入）
7. **Worker 线程泄漏**：`worker.py` 中 `_threads` 列表无限增长不清理，长期运行可能内存泄漏
8. **N+1 查询**：`collections.py` 和 `public.py` 路由存在 N+1 查询问题
9. **重复充值端点**：`routers/auth.py` 和 `routers/billing.py` 都有充值端点，应合并
10. **前端 segments.js**：仍导出 `translateSegment` 但前端已不用，可清理
11. **PublicDetailView/PublicView**：收藏弹窗存在与已修复 Bug 相同的模式（需检查）
12. **asyncio.get_event_loop()**：`anki.py` 和 `main.py` 中 async 函数使用了 `asyncio.get_event_loop()` 而非 `asyncio.get_running_loop()`
13. **推送并发安全**：`anki.py` 的 `_push_self_hosted_sync` 通过 `os.environ` 全局设置同步凭证，并发推送时会互相覆盖

## 12. 安全注意事项

1. **生产环境必须修改**：
   - `ANKI_JWT_SECRET`
   - `ANKI_CREDENTIAL_ENCRYPTION_KEY`
   - 数据库密码
   - 认证服务管理员密码 (`admin@3mudi.com` / `Admin2026!`)
2. **修改密码需验证旧密码**：PUT /api/auth/me 的 `old_password` 校验
3. **推送凭证加密存储**：Anki 同步密码使用 AES-256-CBC 加密
4. **CORS 限制**：仅允许 `https://anki.3mudi.com` 和 `http://localhost:3000`
5. **用户数据隔离**：文件系统按 user_id 分目录，API 查询强制过滤 user_id
6. **认证服务本地调用**：后端通过 `http://127.0.0.1:9000` 调用认证服务，避免公网暴露
